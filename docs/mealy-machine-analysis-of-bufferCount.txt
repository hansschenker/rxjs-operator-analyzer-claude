Mealy State Machine Analysis of bufferCount
Applying the 6-tuple Mealy machine formalism to bufferCount(bufferSize, startBufferEvery):

1. State Space (S)
Code
S = {
  (buffers: T[][], count: ℕ)
    where buffers is a list of active accumulation buffers,
    and count tracks the number of values received
}
More precisely:

buffers: Array of active buffers, each growing toward bufferSize
count: Natural number tracking total input events (modulo arithmetic for cycling)
2. Initial State (S₀)
Code
S₀ = ([], 0)
  buffers = []  (no buffers yet)
  count = 0     (no values received)
3. Input Alphabet (Z)
Code
Z = {
  value: T              (source emits a value)
  complete              (source completes normally)
  error: Error          (source errors)
  finalize              (subscription torn down)
}
4. Output Alphabet (A)
Code
A ⊆ {
  emit(buffer: T[])     (output a filled buffer)
  complete()            (signal end of observable)
  error(e: Error)       (signal error)
  none                  (no output)
}
5. Transition Function (T : S × Z → S)
Let N = startBufferEvery (normalized, never null; defaults to bufferSize).

On value input:
Code
T( (buffers, count), value ) = (buffers', count')

where:
  1. If count ≡ 0 (mod N):
       buffers' = buffers + [[]]  (start a new buffer)
     else:
       buffers' = buffers

  2. For each buffer b in buffers':
       b := b ++ [value]  (append value to buffer)

  3. count' = count + 1

Deterministic & purely functional on state.
Side effect in transition: Buffers that reach bufferSize are marked for emission (recorded in toEmit list).

6. Output Function (G : S × Z → A*)
The output is generated during the transition, determined by buffer fullness:

On value input:
Code
G( (buffers, count), value ) = [emit(b₁), emit(b₂), ...]

where:
  After appending value to each buffer b ∈ buffers:
    - If len(b) ≥ bufferSize:
        emit(b) is added to output queue
        b is removed from buffers (cleanup)
    - else:
        (no output for this buffer)

Returns: Array of emit actions for all full buffers
On complete input:
Code
G( (buffers, count), complete ) = 
  [emit(b) for each b in buffers] ++ [complete()]

(Emit all remaining buffers, then signal completion)
On error input:
Code
G( (buffers, count), error ) = [error(e)]

(Propagate error; implicit cleanup via finalization)
On finalize input:
Code
G( (buffers, count), finalize ) = []  (no user-visible output)

Side effect: buffers := null (memory cleanup)
Mealy Machine Table
State	Input	Output	Next State
([], 0)	value(v)	none	([[v]], 1)
([[v]], 1)	value(v')	none	([[v, v']], 2)
([[v, v']], 2)	value(v'')	emit([v, v''])	([], 3) if N=2
(buffers, n)	complete	emit(b) for all b; complete()	(∅, finalized)
(buffers, n)	error(e)	error(e)	(∅, finalized)
Key State Machine Properties
Determinism: Given state and input, output and next state are uniquely determined.
Cyclical State: count drives an implicit cycle of period N (startBufferEvery).
Orthogonal Outputs: Multiple buffers can emit in the same transition (Mealy multi-output).
Terminal States: After complete, error, or finalize, the machine halts.
Memory Accumulation: State size grows up to ⌈bufferSize ÷ startBufferEvery⌉ × bufferSize elements.

Mealy State Machine Analysis of windowCount
Applying the 6-tuple Mealy machine formalism to windowCount(windowSize, startWindowEvery):

1. State Space (S)
Code
S = {
  (windows: Subject<T>[], count: ℕ)
    where windows is a list of active window subjects,
    and count tracks the total number of values emitted
}
Key difference from bufferCount:

windows stores live Subject instances (observables), not arrays
Each Subject can have multiple downstream subscribers
Windows emit values immediately as they arrive (hot, not cold)
2. Initial State (S₀)
Code
S₀ = ([Subject₀], 0)
  windows = [Subject₀]  (first window already opened and emitted to subscriber)
  count = 0             (no values received yet)
Critical initial side effect: The first window Subject is emitted to the subscriber before any input arrives (line 77).

3. Input Alphabet (Z)
Code
Z = {
  value: T              (source emits a value)
  complete              (source completes normally)
  error: Error          (source errors)
  finalize              (subscription torn down)
}
4. Output Alphabet (A)
Code
A ⊆ {
  emit_window(Subject<T>)        (output a new window observable)
  close_window(Subject<T>)       (complete an existing window)
  emit_value(Subject<T>, value)  (relay value through window)
  complete()                     (signal end of main observable)
  error(e: Error)                (signal error through windows)
  none                           (no output)
}
5. Transition Function (T : S × Z → S)
Let N = startEvery (normalized; defaults to windowSize).

On value input:
Code
T( (windows, count), value ) = (windows', count')

Step 1: Broadcast value to all active windows
  for each window in windows:
    window.next(value)  (side effect: emit through Subject)

Step 2: Check if oldest window should close
  c = count - windowSize + 1
  if c >= 0 AND c % N === 0:
    windows.shift().complete()  (remove & close oldest window)
    windows' = windows \ {oldest}
  else:
    windows' = windows

Step 3: Check if new window should open
  count' = count + 1
  if count' % N === 0:
    windows' = windows' ++ [new Subject<T>()]
    (and emit new window observable to subscriber)
  else:
    windows' = windows'

Return: (windows', count')
Deterministic: State transition is purely functional.

6. Output Function (G : S × Z → A*)
Output is generated during the transition:

On value input:
Code
G( (windows, count), value ) = [
  emit_value(w, value) for all w in windows,
  close_window(oldest) if c >= 0 AND c % N === 0,
  emit_window(new_subject) if (count + 1) % N === 0
]
On complete input:
Code
G( (windows, count), complete ) = 
  [close_window(w) for all w in windows] ++ [complete()]

(Complete all remaining windows, then signal end)
On error input:
Code
G( (windows, count), error ) = 
  [error(w, e) for all w in windows] ++ [error(e)]

(Propagate error through all windows)
On finalize input:
Code
G( (buffers, count), finalize ) = []

Side effect: windows := null, starts := null

Critical Observations
1. Subject as State Carrier
Unlike bufferCount (which uses value arrays), windowCount uses Subject instances as proxies for state:

Each Subject's internal subscriber list represents "who's watching this window"
Window closure is explicitly managed via .complete() calls
The state machine doesn't store values; it relays them.
2. Closing vs. Opening Asymmetry
TypeScript
// CLOSING: based on historical count
c = count - windowSize + 1;
if (c >= 0 && c % startEvery === 0) {
  windows.shift().complete();
}

// OPENING: based on current count (post-increment)
if (++count % startEvery === 0) {
  windows.push(new Subject());
}
This creates a coordinated pipeline:

Oldest window closes after emitting windowSize values
New window opens before next value arrives
Overlap zones allow values to pass through multiple windows
3. Pre-emission Semantic
TypeScript
// Line 104-107: New window emitted BEFORE value arrives
if (++count % startEvery === 0) {
  const window = new Subject<T>();
  windows.push(window);
  subscriber.next(window.asObservable());  // ← emitted to subscriber
}
This is noted in the TODO (lines 100-103): the observable is emitted before it receives values. This is intentional for the sliding-window semantics but worth documenting formally.

4. Error & Completion Propagation
Both error and completion paths drain all windows, ensuring no Subject is left hanging:

TypeScript
// Errors: propagate through windows, then through main stream
while (windows.length > 0) {
  windows.shift()!.error(err);
}
subscriber.error(err);

// Completion: complete all windows, then signal done
while (windows.length > 0) {
  windows.shift()!.complete();
}
subscriber.complete();

T( (buffers, count), value(v) ) = (buffers', count + 1)

Pseudocode:
  count_after = count + 1
  
  Step 1: Check if need to START a new buffer
    if (count % N === 0)  where N = startBufferEvery:
      buffers := buffers ++ [[]]
  
  Step 2: Append value to ALL active buffers
    for each buffer b in buffers:
      b := b ++ [v]
      
      if len(b) >= bufferSize:
        mark b for emission (but don't remove yet)
  
  Step 3: REMOVE full buffers from active set
    buffers' := buffers \ {all marked full buffers}
    
  Return: (buffers', count + 1)


Mathematical Definition:
───────────────────────

Let N = startBufferEvery (normalized)
Let S = bufferSize
Let marked = {b ∈ buffers | len(b ++ [v]) ≥ S}

  buffers' = {
    (buffers ++ [[]]) \ marked,  if count % N === 0
    buffers \ marked,             otherwise
  }
  
  count' = count + 1

G( (buffers, count), value(v) ) = [emit(b₁), emit(b₂), ..., emit(bₘ)]

Pseudocode:
  toEmit := []
  
  for each buffer b in buffers (after appending v):
    if len(b) ≥ bufferSize:
      toEmit := toEmit ++ [b]
  
  Return: [emit(b) for b in toEmit]  (or [] if toEmit is empty)


Mathematical Definition:
───────────────────────

Let marked = {b ∈ buffers | len(b ++ [v]) ≥ bufferSize}

  G( (buffers, count), value(v) ) = {
    [emit(b) for b in marked],  if marked ≠ ∅
    [],                          otherwise (no output)
  }
